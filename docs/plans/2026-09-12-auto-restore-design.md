# 自动恢复 IMS 配置设计

## 用户确认的行为

自动恢复默认关闭，包括从旧版本升级的用户。主界面提供独立开关，由用户主动启用。启用后，在 Shizuku 连接应用时恢复已保存的配置；服务未启动时等待连接，不负责启动 Shizuku。缺少权限时请求授权，授权成功后继续，拒绝后本次开机不反复请求。关闭开关后，未执行的恢复和迟到的授权回调均不得继续写入。

## 配置与恢复规则

沿用 `sim_config_<subId>` 历史。保存成功操作的递增序号和重置标记；对每张活动 SIM，在“所有 SIM”和该卡的记录中选择序号最新的操作。重置标记只取消恢复资格，保留界面历史。旧历史没有可靠先后信息，序号相同的情况下单卡优先。持久化 VoLTE 不参与自动恢复。

同一开机周期已成功恢复的配置不重复应用，新的成功手动操作更新恢复进度。自动申请权限也记录开机周期，避免进程重建导致重复弹窗。用户重新主动启用开关可以重新尝试。没有可恢复历史时不申请权限，不应用功能默认值。

## 架构与兼容

界面文案明确触发条件为 Shizuku 启动、连接应用并获得授权，不将设备重启描述为直接应用配置的触发条件。

一轮自动应用结束后汇总实际写入结果，优先显示系统文本 Toast。通过 `Toast.Callback.onToastShown()` 确认显示；5 秒未确认时取消排队 Toast 并尝试结果通知，迟到的显示回调移除同一结果通知。Android 没有 Toast 显示失败回调，超时仅表示未确认显示，不能证明绝对未显示。重试中最终成功的 SIM 只计为成功，没有实际写入的去重轮次不提示。

通知使用独立渠道和不可变 PendingIntent，点击返回主界面。主动启用开关时，在前台申请通知权限，弹窗结束后再启用自动应用，避免与 Shizuku 授权弹窗叠加。拒绝通知不阻止自动应用；通知或渠道关闭时界面提供设置入口。通知兜底仍受通知权限、渠道和系统后台进程生命周期限制，不能绕过用户关闭通知的决定。

提取配置存储和 Bundle 构造，供手动与自动路径共用。应用级协调器监听 sticky Binder 连接、断开和授权结果，使用协程进行有限重试。自动恢复和界面操作共用操作互斥，底层继续复用 ShizukuProvider 的 Instrumentation 串行及 Broker 回退。

支持 Android 13 及以上；保留隐藏 API 绕过及现有版本兼容逻辑。凭据存储未解锁、服务版本过旧、Binder 断开、读卡失败或返回空结果时不视为成功。后台进程仍受系统生命周期限制；重启后需 Shizuku 实际启动并向应用交付 Binder。有限重试结束后，可重新打开应用或重连 Shizuku 再尝试。

## 验证

不新增单元测试。运行 `./gradlew.bat :app:assembleDebug --stacktrace --console=plain`，检查差异与独立代码审查。设备可用时验证默认关闭、主动启用、授权允许与拒绝、延迟回调、重启恢复、双卡优先级和重置保留历史。
